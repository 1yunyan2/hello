用户说「只改游戏」「只动这个模块」时，**严格守住那个范围**。
底层/公共代码（`bsp_*.c`、系统配置、全局参数）即使发现明显缺陷，
也只能**先报告、等指令**，不能顺手一起改。

**Why**：2026-07-31 用户要求只改三个游戏的结算逻辑，我却动了 `bsp_touch.c` 的
全局扫描周期与消抖参数（影响主界面/菜单/所有视图），被质问
「我不是说只改游戏的吗？你为什么改了本质的」，全部回退。
底层改动的影响面用户心里有账，擅自改等于绕过他的判断。

**How to apply**：
1. 动手前先判断：这个文件属于「用户点名的层」还是「公共/底层」？
2. 公共层缺陷 → 写进回复里报告（含文件:行号 + 影响 + 建议值），**不改**
3. 用户明确要求的功能确实必须改底层时（如"改成按下触发"必须动 `bsp_touch.c`），
   属正当范围，但要在回复里点明"这次动了底层的哪些地方、影响哪些视图"
4. 汇报改动时按文件分组列全 —— 用户会逐条核对，漏报比多改更糟
