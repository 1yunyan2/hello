2026-09-21 重做 `interaction.c` 的 11_x 治愈（全组仅 1 张，`EMO_HEALING1`=48，素材 `治愈2.gif` / `S:/gif/11_1.gif`）。当天做了四轮，后三轮全是用户上板/看代码抓出来的。

**⭐ 素材实测（按 duration 累加的真实时间轴，不数帧序号）**
- `gif_src/11_1.gif`：320×240，**144 帧 / 6000ms / loop=0**；`assets/gif/11_1.gif`：**34 帧 / 6000ms / loop=0**（1g.py 合并重复帧，总时长不变）
- ⚠️⚠️ **loop=0 = 无限循环**。素材里那"3 个 `<`"只是**一个 6 秒套装**；只要不切图，眼睛每 2 秒就再来一次，**永远**。
  ⇒ 「一套里 `<` 有几次」这个问法本身要小心：**屏幕上 `<` 的总次数 = 舵机总时长 ÷ 2000ms**，是舵机那边决定截到哪里。
- **三个循环的时长并不相等**（上机文件实测每帧时长）：

  | | 展开 | 峰停 | 收回 | 基停 | **循环总长** | 睁满时刻(累计) |
  |---|---|---|---|---|---|---|
  | 循环 1 | 290(7帧) | 750 | 130 | 870 | **2040ms** | **290ms** |
  | 循环 2 | 250(6帧) | 750 | 130 | 870 | **2000ms** | **2290ms** |
  | 循环 3 | 250(6帧) | 750 | 130 | 830 | **1960ms** | **4290ms** |
  | | | | | | **合计 6000ms** | |

  ⇒ 之前一直按"每循环恰好 2000ms"算，**从第一循环起就有 40ms 的错**。
- ⭐**上升/下降极不对称**：睁满要 **290ms**，闭回只要 **130ms**（"慢慢睁开、啪一下闭上"）。这条是"手臂跟不上"的物理根源之一（见下）。
- 动的部位左右极不对称（右半 x≥160：942→**4070px ×4.32**，一帧吃掉 66% 行程；左半 x<160：945→1490 ×1.58 只上抬加粗）——这才是本组的性格
- ⚠️ 差点误判：**非透明像素质心**报 x 漂 44.7px 像真位移，实为右眼侧多约 3670 像素把质心拽偏。**判据要改用 bbox + 分区质心。**
- ⇒ 舵机动作**无从照抄只能自己发明**（同 [[shy_6x_redesign]] [[ticklish_7x_redesign]] [[surprised_8x_redesign]]）

**🔴🔴 第二轮：相位漂移（用户上板前看出来的）**
用户原话：「在眼睛进行 `<` 时候手臂同时动，因为单张 GIF 好像循环三次这个眼睛 `<` 的动作？但是手臂只在第一次和 GIF 的 `<` 搭配起来了」。首版两臂周期 **2700ms** vs 素材 2000ms ⇒ 每循环多 700ms，3 循环累计漂 ~2.1s，**正好漂掉一整拍**（量化证据：第 2 个 `<` 完全反相，眼开时臂高 30° / 眼闭时 63°）。
- ★★**教训（同 [[surprised_8x_redesign]] 的毛病）**：首版注释写"只做 2 个周期，因为 3 次显机械感、治愈贵在静"——**那是事后给自己找的理由**，真实原因是我按自己的 2700ms 节奏数了 2 次。**素材循环 N 次就老实做 N 次、周期严格对齐；节奏与素材不一致时累计漂移迟早把相位翻反。**
- ★**「配合」只能落成①时间锁相，不能落成②形状对应**：手臂只有一个前抬自由度，"眼睛放大"翻译过来只能是"抬更高"，那是把形状当语义（8_x 编错映射的同一个错法）。

**🔴🔴🔴 第三轮：我查到了真机制，但也因此【误杀了一个正确假设】**
- ✅ **查到的确定事实**：`interaction.c:2626` `xSemaphoreTake(s_ia_d1_2_sem, 10s)` —— `interaction_play_blocking` **阻塞等舵机序列跑完**；`interaction.c:2650` `ui_resume_main_gif_loop()` —— 舵机一完**立刻**恢复主界面。
  ⇒ **一次情绪的时长 == 舵机序列的时长**，GIF 只是被"到点硬切"（GIF 自己无限循环，切在第几拍全凭时长碰巧）。
  ⇒ 约束之一：**舵机总时长不能超过 GIF 循环周期的整数倍**，否则多出的零头会露出下一个 `<` 再被切掉。
- ⚠️⚠️ **但同一轮我犯了大错**：我据此断定"两套时钟走散"是伪命题，把第二轮加上的 δ 全撤了（840→740）。**这是错的。**
  **用户在硬件上亲手把 740 改成 1000，并说「虽然有停顿，但是正好和眼睛的 `<` 搭配起来」** ——
  ⇒ **δ（GIF 走得比名义慢、手臂要跟着拉长）是真的**，只是它和"总时长不能超整数倍"是**两个独立约束，我当时把它们混成一个**。
  ★教训：**"查到一个新机制"不等于"之前所有解释都作废"**。新证据只该排除与它直接矛盾的假设，不该顺手把别的结论一起推翻。
