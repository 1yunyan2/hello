2026-09-22 交付：`docs/情绪动作_白话版.csv`（41 条情绪 × 头/左臂/右臂），给非开发人员看。

**Why**：用户要一份"设计师/非开发人员能看懂"的动作说明，不是代码值。第一版我写了"设计含义（推断）"列，被否；第二版写了代码值表，被否（"有些复杂"）；第三版先概括写"向右来回4趟"，被否——用户要的是**逐步叙述**："从初始角度到序列起始角度、用什么速度；然后向左/向右、什么速度、运动多少角度"。

**How to apply**：
- **列只有 5 个**：编号 | 情绪名 | 头部怎么动 | 左手怎么动 | 右手怎么动。不要"设计含义"列（用户明确"没让你猜测设计意图，不需要"）。
- **每格内容**：`【初始姿势】` → `【起始】起点 → 终点，速度词` → `第N步：方向 X°，速度词，停 Y 秒` → `【结束归位】`。头部格末尾附速度对照表。
- **速度词（用户定稿）**：很快=5 / 快=10 / 中速=15 / **慢=20** / 很慢=25 / 极慢=50（ms/度）。
- **方向依据**（查证过，别猜）：头部 [bsp_config.h:76-77]、`HEAD_MIN_ANGLE 10` 注释"向左极限"、`HEAD_MAX_ANGLE 170`"向右极限" ⇒ **角度变大=向右**；手臂 [bsp_servo.c:600] "逻辑角 0~180，中位 90，前+后−" ⇒ **角度变大=向前**；初始姿势 头 90=[bsp_config.h:329]、臂 **15**=[bsp_config.h:330] `ARM_CENTER_DEG`。
- **生成脚本** `_tools/gen_emotion_table.py`：直接从 interaction.c 解析（含**剥一层** `//` 还原被注释的 37 条），速度宏从 bsp_config.h 读，不硬编码。**手抄 3000 行必错，别手抄。**
- 🔴 **脚本大坑**：剥 `//` 只能剥**一层**。7_x 条目里有多余的备用步进被**额外注释一层**（`//  {15.0f, ...},`），剥两层会把它们当真步数，seq_len 自检从 4 处误报成 14 处。
- ⚠️ 跑脚本要 `PYTHONIOENCODING=utf-8`，否则 GBK 控制台里 emoji 打印会崩。

**解析中查出的 4 处 `seq_len` 与实写步数不符**（均在**已注释**的旧条目里，当前固件不受影响，但一旦解注释就会发作）：
| 条目 | 位置 | 问题 |
|---|---|---|
| 1_5 头部 | 步进 interaction.c:410-418（9 步）、`seq_len` :420 | seq_len=8 ⇒ 末步 `{90.0f}` 被丢，收不回中位 |
| 3_3 头部 | 步进 :988-993（6 步）、`seq_len` :995 | seq_len=5 ⇒ 丢末步 `{92.0f, SERVO_SPEED_MID}` |
| 3_4 左臂 | 步进 :1066-1071（6 步）、`seq_len` :1073 | **seq_len=8 > 实写 6** ⇒ 多读 2 个零值元素 |
| 3_4 右臂 | 步进 :1080-1085（6 步）、`seq_len` :1087 | 同上 |

`seq_len` 写大了更危险：[servo_manager.c:215] `for (s = 0; s < src[i]->seq_len && n < BSP_SERVO_SEQ_MAX_POINTS; s++)` 只按 seq_len 循环，数组是 `static const` 零初始化 ⇒ 会读到 `{0.0f,0,0}`，等于命令舵机转到 0°。
