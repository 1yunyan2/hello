2026-09-21 重做 `interaction.c` 的 14_x 舒服三组（`EMO_COMFORTABLE1~3`，值 53/54/55）。

**逐帧拆素材（用 duration 累加的真实时间轴）**
- `14_1.gif` 144 帧/6000ms。**周期恰好 24 帧 = 1000ms，整 6 个循环**。bbox 宽**恒定 191px**（零水平位移/缩放），只有质心竖直 **114↔118 = 4px** 浮动。画面 = 弯月笑眼 + 两个腮红点 + 微笑嘴的笑脸，**整张脸一起上下起伏**，无局部单独动。
- `14_2.gif` 128 帧/5330ms。周期 **16 帧 = 667ms，整 8 拍**。上沿 y 78→71（升 7px）、质心 y 122→118、宽 138↔128（**收 10px**）⇒ **以脸为中心的上下缩放**，零旋转零平移。画面 = 眯眼（^^ 波浪眉）+ 大微笑。★素材名里的"打滚"在画面上**不存在旋转**，舵机抄不到。
- `14_3.gif` 144 帧/6000ms。**周期 48 帧 = 2000ms，整 3 个循环**。画面 = 同一张笑脸 + **红心一颗颗从下往上冒**。逐帧数红心：t=130~330 左眼位一颗 y132→66；t=420~580 右眼位 y113→71；t=670~880 右侧 y117→64；**t≈1170~1670 一次同时冒 4~5 颗**（红心像素从 ~350 暴涨到 1666）。

**🔴 本次新增的三条硬件/执行层事实（前几组全都不知道）**
1. **手臂 `.target = 45°` 不等于 45° 行程**——基线 `ARM_CENTER_DEG`=**15°**（见 [[curious_4x_redesign]]），所以 15↔45 只有 **30°**。我第一版按 45° 折算行程，`680ms` 与实际 `460ms` 差一大截。
2. **归中的速度不是动作速度**：头归中 `SERVO_SPEED_CENTER`=**MID(15)**，**臂归中 `SERVO_SPEED_CENTER_ARM`=FAST(10)**。45→15° 的臂归中是 30°×10 = 16 帧 **320ms**，不是按 MID 算的 460ms（第二版因此差 140ms）。
3. **末步若已停在归位角（如 15°），归中段是零位移 20ms 而不是一整段行程**——14_1/14_2 两臂末步收在基线 15°，我第一版把它当整段 320ms 算，整轴差了 300~400ms。
4. **帧量化向上取整**：`frames = floor(位移×ms/度 ÷ 20) + 1`，故 30°@MID 不是 450ms 而是 **460ms**
   ⚠️⚠️ **2026-09-21 本条公式已作废**（做 1_6~1_9 时重读 bsp_servo.c:1613 查证，当时代码或已不同）：
   现行为 `frames = int(位移 × step_ms) // own_fm`（**整除、无 +1**），且真正的每帧耗时是
   `per_frame × base_frame_ms` 而非 `own_fm` ⇒ 30°@MID 实为 **440ms**。
   完整修正见 [[reference_servo_frame_timing]]。**下面所有按 460/680/420 折出来的时间线都要按新公式复算。**、45°@MID 不是 675 而是 **680ms**、40°@FAST 是 **420ms**、26°@MID 是 **400ms**、14°@SLOWER 是 **300ms**、12°@SLOWER 是 **260ms**、10°@SLOWER 是 **220ms**、10°@MID 是 **160ms**。
   ⚠️ **我第一版整组把 30°@MID 当 450ms，12 步算出"6000ms"，实际 12160ms——正好差一倍。** 这是本组最大的坑。

**✅ 本组采用的校验手法（比 7_x/8_x 那版再加固）**
Python **配对花括号解析真代码**（正则找 `\.head\s*=\s*\{` 后逐字符配平，**不要用非贪婪正则**——会被 seq 内层 `},` 截断）→ 按 `servo_manager.c:185-264` 语义组点（target + seq + 归中）→ 按 `frame_ms=20` 重放。脚本同时断言：
① 每轴总时长 == 素材周期的整数倍；② 点数 ≤ `BSP_SERVO_SEQ_MAX_POINTS`(34)；③ **每帧位移 ≥ 死区 0.8°**；④ 没有负 hold（我中途写出过 `{15.0f, 0, -20}`，`hold_ms` 是 uint32_t，**负数会绕成天文数字**）。
本次靠它抓出两轮错（差一倍、差 140ms）。

**三组设计（主语都是两臂，头退居注脚——手臂才有"舒展/缩/顶"的自由度，头只有偏航轴）**
- `14_1` **同相轻快**：两臂逐字相同，15↔45°(30°)@**FAST** 320ms + 停 177ms = **半步 497ms，一次完整起伏 994ms ≈ 素材 1000ms**，共 **6 次**。头 116→130→118 **单向偏左不来回**（承 [[curious_4x_redesign]] 的"定向→停留"）。
- `14_2` **同相深缩舒**：两臂 15↔55°(40°)@FAST 420ms + 停 242ms = **半步 662ms，一次 1324ms，只 4 次**。头 110→124→112，同样单向偏左。
  ★**刻意不追素材的 8 拍**：40° 在 FAST 下光行程 420ms，凑 8 次要 16 步（≈9.8s）或把 hold 压到 ~30ms——前者太长，后者等于"纯位移机械链"（正是用户最早说"别扭"的成因）。取舍 = **保住幅度和停顿，次数减半，总时长仍落在素材拍边界**（5336 = 667×8，GIF 正好走完一个完整循环再切）。
- `14_3` **错开起手的涟漪顶**：两臂 15↔45°(30°)@**MID** 460ms + 停 533ms = **半步 993ms ≈ 素材 2000ms 周期**，左臂 6 步（3 次上顶）、右臂**首步零位移等 675ms** 后走 5 步（末位停在 45° 交归中放下）。头 100↔122 做 **4 次偏置往复**（全程 >90° **绝不跨中位**，按 [[shy_6x_redesign]] 判据是"舒服得蹭"不是摇头）⇒ 与 14_1/14_2 的"头只单向偏"形成第三种头部语言。
  ★**675ms 这个滞后是解方程解出来的**：左臂 6 步恰好装满 6000ms，右臂少一步且末位在 45° 要多走 320ms 归中，倒推滞后只能是 675ms。（旋钮：每减 332ms 少错开半步。）

**三组的差异维度**：14_1 幅度 30°/6 次/半步 497ms、14_2 幅度 40°/4 次/半步 662ms、14_3 幅度 30°+两臂错开 675ms/半步 993ms。速度档 FAST/FAST/MID，头分别是"单向偏"/"单向偏"/"偏置往复"。

**时长对齐**（承 [[healing_11x_redesign]]）：14_1 三轴均 **6000ms** = 6×(1000ms)；14_2 三轴均 **5336ms** = 8×(667ms)；14_3 三轴均 **6000ms** = 3×(2000ms)。三条都落在素材拍边界上。
🔧 微调旋钮 = 总时长；实测法 = 日志里"舵机开始/舵机结束"两行的时间差。
