**🔴🔴 首版最大的错误：我自己编了一条不成立的映射，还把它当成"最有价值的发现"**

> 首版我写了一条「**素材里"眼睛"动不动 ⇒ 头该不该有戏**」，并据此把 **8_3 的头整体钉死**（`.head = {0}`）。
> 用户在**上板前看代码**就指出了三条头部的毛病，复核后确认这条映射**根本不成立**：
> - **它的真实来源是"要给 8_3 找一个和 8_1/8_2 不同的差异点"，而"头钉死"是最省事的那个** —— 先有结论，再包装成"忠实素材"。我在汇报里还称它"本次最有价值的一条映射"，是典型的过度自信。
> - 逻辑上也站不住：素材里"眼睛不动"只说明**没有眨眼/星星闪烁**，说明不了**头和身体冻住**。真人抱住东西时头照样会靠过去、会呼吸。
> - 兜底判据：**头是脸上唯一的关节，5.3s 一动不动读起来是"坏掉"，不是"情绪"。**

**✅ 复核后定下的三条硬原则（后面 9_x~14_x 照此执行）**
1. **头不许出现"整条钉死几秒"的设计。** 素材里脸在动，头就该一直在动；哪怕幅度小。
2. **头的动作必须比四肢慢一档、软一档。** 给手臂用 `VERY_FAST` 是对的（抽泣/惊跳需要那个"噌"），但同样 60ms 走 12° 搬到头上就不是"屏息"而是"**舵机打嗝**"。★同一条速度档在头和臂上不是一回事。
3. 头可以和四肢**同拍**（全身一起使劲时是对的），也可以**差一倍拍**（分层），但**绝不能同速同幅** —— 那等于把头和胳膊焊在一起。

**设计定稿（三条互不复用）**
- **8_1** = 【惊 → 喜 两段】头承担"惊"：猛偏左 36° → **僵住 300ms**（那"一顿"就是受惊本身）→ 不再钉死，续 8 拍 24° 全幅颤；两臂弹到 140° 后 6 拍【快降 35°@VERY_FAST(175ms) + 慢升 35°@FAST(350ms) = 525ms/拍】，★**全程无停顿**且升降不等速 ⇒ "一抽一抽"，不是对称匀速摆。**头是三条里最活跃、幅度最大的**（8_1 头的 24° 全幅 = 本组唯一有摇头风险处，已标注上板重点看）。
- **8_2** = 【憋-放】**那个"憋"只给手臂**：每拍【收 24°@VERY_FAST(120ms) + ★憋住 130ms + 放 24°@FAST(240ms) = 490ms/拍】×8；头**同拍但不同速**（MID，软 3 倍），93↔105 + 柔停 130ms = 490ms。
- **8_3** = 【抱 + 靠】最慢最柔：两臂周期 660ms 且★**没有顿挫**，一路合抱 163° 再柔和收放 6 个来回（130↔163，33° 全幅 @FAST）；头【靠过去 + 呼吸】，节拍 1320ms **是两臂的 2 倍** ⇒ 两臂"抱紧-放松"、头"慢慢点头"，两层叠起来 = 窝在怀里呼吸。

**★校验手法（沿用 7_x 的 Python 重放，本次升级成"解析真代码"而不是"重放设计参数"）**：写完不编译，用配对花括号解析 `interaction.c` 里 8_x 块的真实文本 → 断言 `seq_len` 与实际步数一致 → 按 `servo_exec_seq` 语义累加三轴时间线 → 卡 `点数+1 ≤ 34` / `seq_len ≤ 32`。
⚠️ 踩到的坑：① 用非贪婪正则提取 `.right_arm = {...}` 会被 seq 内层的 `},` 提前截断，**必须用花括号配对**；② seq 步里的 speed 常写成字面量 `0`，解析时不能只查宏表（`KeyError: '0'`）。
