# BUG-038 命中锤子不显示（阻塞震动吃掉动画寿命）

**现象**：打地鼠敲中地鼠时锤子**直接不出现**；空敲（敲空洞）却能正常看到锤子。

**根因**：`game_whack.c` 命中分支里的 `bsp_motor_pulse()` 内部是
`bsp_motor_set(100) + vTaskDelay(30) + bsp_motor_set(0)`，**在 LVGL 线程原地阻塞 30ms**。

命中路径时序（原代码）：
1. `try_hit()` 显示锤子 → 记 `hammer_t0 = 现在`
2. `bsp_motor_pulse()` → **卡 30ms**
3. 引擎下一帧查 `now - hammer_t0 >= WHACK_HAMMER_SHOW_MS` → 已满足 → 立刻收回锤子

锤子寿命被震动阻塞整个吃光，屏幕根本没机会刷出来。
**空敲分支没有 `bsp_motor_pulse()`**，不阻塞 → 锤子撑到下一帧被渲染 → 这就是两者差异的来源。

**为什么以前没暴露**：`WHACK_HAMMER_SHOW_MS` 原值 120ms，被吃掉 30ms 还剩 90ms 够渲染。
用户把它调到 30ms 后（想让连敲更跟手），恰好等于阻塞时长，问题才显形。
⚠️ 教训：**参数调小会让原本被余量掩盖的阻塞型 bug 突然现形**，别只怀疑刚改的那个参数本身。

**修复**（2026-07-31，已改未编译未烧录）：
- `game_whack.c` 新增 `g.motor_t0` 字段
- 命中震动改**非阻塞**：`bsp_motor_set(BSP_MOTOR_DEFAULT_STRENGTH)` + 记时刻，并**挪到 mole/hammer 渲染之后**
- 引擎回调里按 `WHACK_MOTOR_MS` 到点 `bsp_motor_set(0)`
- `whack_stop()` 兜底关马达（退出时引擎已停，没人关它会一直震）
- `whack_sprites.h` 新增 `WHACK_MOTOR_MS 30` + 警告注释「不要改回 bsp_motor_pulse()」

**同类隐患**：`bsp_motor_pulse()` 在任何 LVGL 定时器/回调上下文里调用都会卡住整个 UI 线程 30ms。
`bsp_touch.c` 的耳朵震动也曾有同样问题（见 [[daily-2026-07-31-游戏结算与触摸触发改造]]，已改成标志位延后震动）。
排查同类问题的指纹：**「A 分支看得到、B 分支看不到」且 B 分支多一个阻塞调用**。
