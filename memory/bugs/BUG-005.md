# BUG-005 HTTP 认证返回 201 被当作失败处理

**状态**：已修复
**发现日期**：2026-04-07
**修复提交**：`d5adbba` feat: auth兼容HTTP 201 + WS地址切换 + LCD驱动新增
**文件**：`main/protocol/auth.c:74`、`main/protocol/auth.c:182`

## 现象
设备首次向服务端注册时，服务端返回 `HTTP 201 Created`，
客户端判断 `status_code != 200` 为真，将成功请求判定为失败，
不提取 accessToken，导致后续 WebSocket 连接无 Token。

## 原因
HTTP POST 创建新资源时，规范允许（有时要求）返回 201 而非 200。
原代码只检查 `!= 200`，未考虑这种常见情况。

## 修复
**文件**：`main/protocol/auth.c`
```c
// 修复前
if (status_code != 200) { /* 报错 */ }

// 修复后
if (status_code != 200 && status_code != 201) { /* 报错 */ }
```

## 教训
HTTP 认证接口务必同时兼容 200 和 201，甚至可扩展为 `status_code / 100 != 2`（2xx 均视为成功）。
