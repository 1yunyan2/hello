## 症状（两条独立现象）

### 现象 A：多轮第二句卡 9~10 秒 + 云端报错


## 根因

### 根因 A：COMPLETE 事件错误清掉 SERVER_READY_BIT

[session.c:815-832](main/session/session.c#L815-L832) `PROTOCOL_EVENT_COMPLETE` 处理在多轮模式下执行：
```c
xEventGroupClearBits(s_session_eg, SESSION_SERVER_READY_BIT);  // ← 致命
```

但**多轮模式不会发新的 start/Started 握手**，SERVER_READY 一旦被清，**再没有任何事件能把它重新置位**：
- `ws_sender_task` [L890](main/session/session.c#L890) 在 READY=0 时 `continue` 不读 enc_output
- → encoder 持续编码，enc_output 撑爆 → 丢帧
- → 上行根本没数据 → 云端报 "buffer too small"

### 根因 B：尾端字保护被持续噪声持续覆盖

[session.c:460-463（旧版）](main/session/session.c#L460-L463)：
```c
if (s_speech_detected && vad == VAD_SILENCE && avg_amp > 100)
    vad = VAD_SPEECH;  // 强制覆盖
```

原意是救"啦/啊/吗"低能量尾字，但风扇/空调噪声 `avg_amp` 稳定 > 100 也会过线：
- 用户说完话 → AFE 判 SILENCE
- 风扇噪声 avg_amp 100+ → 被强制改回 SPEECH
- [L498](main/session/session.c#L498) `xTimerStop(s_eos_timer, 0)` 每帧把 EOS 定时器掐掉
- → 永远等不到 600ms 静音 → 永远不发 stop
- → 录音持续到 enc_output 满（~25 秒后才偶然抖到 avg_amp<100 触发 EOS）

噪声门 [L435](main/session/session.c#L435) `s_speech_detected ? 50 : 150` 帮了倒忙——确认人声后阈值从 150 降到 50，风扇 50~150 振幅全过线。

## 修复

### 修复 A：L830 ClearBits → SetBits

```c
// COMPLETE 多轮分支
xEventGroupSetBits(s_session_eg, SESSION_SERVER_READY_BIT);  // 维持就绪态
```

语义上更准确的写法是"删除这行"（READY 已由 TTS_STOP set），SetBits 等价但语义稍糊；功能上两者都让 ws_sender 能继续抽水。

### 修复 B：尾端字保护 800ms 熔断（方案 A）

新增静态变量 `s_first_silence_tick` + 常量 `TAIL_PROTECT_MAX_MS = 800`。

[session.c on_enhanced_pcm](main/session/session.c) 改造尾端字保护：
```c
if (s_speech_detected && vad == VAD_SILENCE && avg_amp > 100) {
    if (s_first_silence_tick == 0)
        s_first_silence_tick = xTaskGetTickCount();
    uint32_t silence_ms = (xTaskGetTickCount() - s_first_silence_tick) * portTICK_PERIOD_MS;
    if (silence_ms < TAIL_PROTECT_MAX_MS)
        vad = VAD_SPEECH;     // 800ms 窗口内：救尾字
    // else: 放手交回 AFE VAD
}
else if (vad == VAD_SPEECH) {
    s_first_silence_tick = 0;  // 收到真语音帧，重置窗口
}
```

效果：尾字最多撑 800ms（"啦啊吗"长元音不可能更长），超过就让 EOS 正常推进，风扇噪声钻不进来。

### 修复 C：单句最大时长 8s 硬切（方案 B 兜底）

新增静态变量 `s_speech_start_tick` + 常量 `UTTERANCE_MAX_MS = 8000`。

- 在 `s_speech_detected` 由 false→true 处记录 `s_speech_start_tick`
- 在每帧末尾检查：超过 8s 强制发 `SESSION_EVT_VAD_STOP` 队列消息（与 `on_eos_timeout` 行为一致）

正常对话一句不超过 6s；8s 给足余量。即使方案 A 失效（异常 VAD/噪声谱），也能兜底切断。

### 修复 D：状态切换点同步清零

在 7 处入口同步清 `s_first_silence_tick = 0; s_speech_start_tick = 0;`：
- `PROTOCOL_EVENT_TTS_START`、`TTS_STOP`、`COMPLETE`
- `session_close`
- `session_on_wake_word`（打断分支、新会话分支、error 分支）

避免上一轮残留 tick 让方案 B 在新一轮一开始就误触发。

## 启示

- **多轮模式下"就绪态"维护要小心**：握手类事件位（SERVER_READY）在没有"新握手"动作的状态切换里不能轻易清。每次 Clear 都要问一句"谁负责再 Set 回来？"
- **任何"强制改判"逻辑都要有熔断**：单纯振幅门兜不住持续噪声，必须叠加时间窗（"最多救 800ms"）或 peak/avg 比值（持续噪声 peak/avg < 2，人声 3~6）。
- **硬切兜底永远要有**：再聪明的 VAD 也会被异常输入钻空子，单句最大时长是最后一道兜底，不依赖任何感知逻辑。
