## 症状
LLM 回复较短（< buffer 阈值，约 4KB）时一切正常；回复变长后串口看不到 `收到文本帧: { ... }` 整段日志，只有 `JSON 解析失败` 警告刷屏，UI 情绪状态、TTS 触发全部不工作。

## 根因
旧代码 [websocket_client.c:333（旧）](main/protocol/websocket_client.c)：
```c
if (data->op_code == 0x01) {
    ESP_LOGI(TAG, "收到文本帧: %.*s", data->data_len, data->data_ptr);
    cJSON *root = cJSON_ParseWithLength(data->data_ptr, data->data_len);
    ...
}
```
假设"一次 `WEBSOCKET_EVENT_DATA` callback = 一条完整 JSON"。但 esp-websocket-client 对超过单帧接收 buffer 的文本帧会**按 buffer 大小自动分片**，每片各发一次 callback，靠 `data->payload_offset / data->payload_len` 标识当前位置。原代码每片都尝试解析片段 → cJSON 必然失败。

## 修复
[websocket_client.c:331-440](main/protocol/websocket_client.c#L331-L440) 引入静态重组缓冲：

```c
static char *s_text_rx_buf = NULL;
static int s_text_rx_offset = 0;
static int s_text_rx_total_len = 0;

if (data->payload_offset == 0) {
    // 新消息：释放旧 buf，按 payload_len+1 分配
    if (s_text_rx_buf) free(s_text_rx_buf);
    s_text_rx_total_len = data->payload_len;
    s_text_rx_buf = malloc(s_text_rx_total_len + 1);
    s_text_rx_offset = 0;
}

if (s_text_rx_buf && s_text_rx_offset + data->data_len <= s_text_rx_total_len) {
    memcpy(s_text_rx_buf + s_text_rx_offset, data->data_ptr, data->data_len);
    s_text_rx_offset += data->data_len;
} else {
    // 分片错乱或溢出：丢弃整条
    if (s_text_rx_buf) free(s_text_rx_buf);
    s_text_rx_buf = NULL; s_text_rx_offset = 0; s_text_rx_total_len = 0;
    return;
}

if (s_text_rx_offset >= s_text_rx_total_len && s_text_rx_total_len > 0) {
    s_text_rx_buf[s_text_rx_offset] = '\0';
    cJSON *root = cJSON_Parse(s_text_rx_buf);
    // ... 按 type 路由 ...
    free(s_text_rx_buf); s_text_rx_buf = NULL; ...
}
```

## 验证
- 短消息（hello/started）：仍走"一片即完整"路径，行为不变。
- 长消息（LLM 长回复 / iot 大列表）：串口先打多条 `收到文本帧分片: ...`，最后一片到达时打完整 `收到文本帧: { ... }` 并触发对应 handler。

## 待观察
- **单实例 static buf 不支持并发交叉**：esp-websocket-client 单连接 callback 串行，目前安全。若后续多路复用或多连接需重新设计成 per-client 重组上下文。
- **buf 永驻最后一条大小**：当前实现每条新消息都 free 旧 buf 再 malloc，无 fragmentation 风险但会有反复 alloc/free。如发现 PSRAM 碎片，可改成 high-water-mark 复用策略。

## 启示
WebSocket 客户端的 callback **永远不要假设单次 = 单消息**，必须看 `payload_offset / payload_len`。同样的坑也存在于 binary 帧（`op_code == 0x02`）的大 OPUS 块场景，目前我们的音频帧 < 1KB 不会触发，但要警惕。
