# BUG-006 MultiNet 检测循环占满 CPU 导致 AFE ringbuffer 溢出

**状态**：已修复
**发现日期**：2026-04-09
**修复提交**：`24d10cc` feat(wifi): 修复按钮监控任务创建参数错误（合并提交）
**文件**：`main/wake_word/custom_wake_word.c`

## 现象
设备运行一段时间后 AFE ringbuffer 报 overflow 警告，
偶发唤醒词漏检，音频数据丢失。

## 原因
`audio_feed_task` 的 fetch 循环中，每次循环执行多次 `afe_handle->fetch()` + `detect()`，
未限制单次循环的 detect 次数，当语音数据积压时进入紧凑循环，
连续占用 CPU 数百毫秒，使 AFE 无法及时排空 ringbuffer。

## 修复
**文件**：`main/wake_word/custom_wake_word.c`
限制每次 fetch 最多执行 **1 次** detect 操作，
让出 CPU 给 AFE 数据管道，避免缓冲溢出。

## 教训
MultiNet detect 是计算密集操作，绑 CPU1 也不能无限制调用。
每次 fetch 调用 1 次 detect 是官方推荐模式。
