# BUG-016 — ES8311 麦克风数据异常的硬件诊断指纹

**日期**：2026-05-15
**分支**：two / three / four 同时复现（与代码版本无关）
**模块**：`main/bsp/bsp_codec.c` + ES8311 物理走线
**结论**：纯硬件问题（焊接/连线），代码无修改

## 现象快速识别表

[bsp_codec.c:296-318](main/bsp/bsp_codec.c#L296-L318) 的 `[PCM诊断]` 打印里如果出现以下任一模式，直接定位到硬件：

| 原始 bytes 模式 | peak/rms | 含义 | 排查方向 |
|---|---|---|---|
| `0000 0000 0000 0000` | peak=0 rms=0 | DIN 完全没数据 | GPIO15(DIN) / MCLK / BCLK 任一断线或 ES8311 没启动 |
| `FFFF FFFF FFFF FFFF` | peak 高 rms 低 | DIN 悬空被上拉吃住 | GPIO15 焊点断开，ES8311 ASDOUT 没接到 |
| **`0077 0077 00C7 00C7 ...`**（高字节恒 0x00、采样两两重复） | peak 突然 32768 | I2S 位宽/帧对齐错位 | BCLK/WS 不稳；或 ES8311 寄存器格式与 ESP32 I2S slot 配置不一致 |
| 段 A FFFF / 段 B 0000 / 段 C 杂值 反复切换 | 不稳定 | 接触瞬通瞬断 | 经典虚焊，DIN/BCLK/MCLK 任一虚焊都会这样 |

**特别注意**：peak=32768 (0x8000) = int16 满幅负值出现 → 几乎可断定有一次读到了 MSB=1 的杂字节被当采样头位用，**绝大多数是硬件错位，不是 AFE/VAD 阈值问题**。

## 当前引脚映射（2026-05-15 PCB 新版布局）

[bsp_config.h:121-126](main/bsp/bsp_config.h#L121-L126)：

```
SDA=16  SCL=17           ES8311 I2C 控制
MCLK=8  BCLK=46  WS=7    I2S 时钟三件套
DIN=15  ← 麦克数据（ES8311 ASDOUT → ESP32）
DOUT=6  → 喇叭数据
```

**Why**：8f0b866（2026-05-14）整体重排所有 codec 引脚（旧布局：SDA=8 SCL=15 MCLK=17 BCLK=9 WS=5 DIN=4），动机是修 GPIO14 FSPIWP/SUBSPIWP 复用（[[BUG-015]]）。**当前 PCB 是按新引脚手焊的**，所以代码引脚不需要回滚。

**How to apply**：下次怀疑"代码改坏了麦克风"时，先用 `git diff` 看 [bsp_config.h](main/bsp/bsp_config.h)；如果引脚和 PCB 走线一致，立刻转去查硬件，不要钻代码牛角尖。

## 排查路径（已沉淀，下次直接抄）

按成本递增：

1. **重熔补焊** ES8311 的 ASDOUT(→GPIO15) / BCLK(→GPIO46) / MCLK(→GPIO8) 引脚根部。QFN 封装一定要加助焊剂
2. **万用表蜂鸣档** 点测三根线 ESP32 焊盘 ↔ ES8311 引脚根部
3. **示波器** 量：
   - GPIO8 MCLK 应 ~4.096 MHz 稳定方波
   - GPIO46 BCLK 应 ~512 kHz
   - GPIO7 WS 应 16 kHz、占空比≈50%
   - GPIO15 DIN 应跟随 BCLK 切换的 PCM 流
4. **I2C ACK** 抓 GPIO16/17 看 ES8311 地址 0x18 是否 ACK，NACK 则查供电/复位
5. **ES8311 自身**：VDDA/VDDD、RESET 拉高、晶振起振

## 不浪费时间的诊断捷径

[bsp_codec.c:257-280](main/bsp/bsp_codec.c#L257-L280) 启动期会做 `[PCM自检]`，塞已知值算 peak/rms。**只要这一行打印的 peak=12345 通过**，就证明诊断统计代码可信，后续 `[PCM诊断]` 的数值都是真实采样反映；可以跳过"是不是诊断代码有 bug"这条岔路。
