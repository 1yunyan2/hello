# BUG-010：LVGL task 栈在 SPIRAM + GIF 读 SPIFFS Flash cache 冲突

## 状态
✅ 已修复（2026-04-26）

## 症状
LVGL 初始化成功、第一帧 GIF 也成功显示，但下一帧 GIF 解析时崩溃：

```
assert failed: spi_flash_disable_interrupts_caches_and_other_cpu
cache_utils.c:152 (esp_task_stack_is_sane_cache_disabled())

Backtrace:
  lvgl_port_task (esp_lvgl_port.c:242)
  → lv_timer_handler (lv_timer.c:71)
  → gif_next_frame_task_cb (lv_gif.c:688)
  → GIF_playFrame → GIFParseInfo → readFile (gif.c:228)
  → lv_fs_read (lv_fs.c:247) → fs_read (lv_fs_posix.c:164)
  → vfs_spiffs_read → SPIFFS_read → spiffs_phys_rd
  → esp_partition_read → esp_flash_read
  → spi1_start → cache_disable() (spi_flash_os_func_app.c:70)
  → spi_flash_disable_interrupts_caches_and_other_cpu → assert ❌
```

## 根因

[ui_port.c:103](main/ui/ui_port.c#L103) 之前配置：
```c
const lvgl_port_cfg_t lvgl_cfg = {
    .task_stack = 8192,
    ...
    .task_stack_caps = MALLOC_CAP_SPIRAM   // ← 元凶
};
```

LVGL task 栈分配在 SPIRAM。但 LVGL GIF widget 每帧都通过 lv_fs_posix → SPIFFS 读取 Flash。
ESP-IDF 在执行 SPI Flash 操作时**必须临时关闭 cache**（`spi_flash_disable_interrupts_caches_and_other_cpu`），
而 SPIRAM 通过同一 cache 访问，cache 关闭期间 SPIRAM 不可访问。
任务栈在 SPIRAM 的任务此时若尝试访问栈（push/pop/局部变量）→ panic。

ESP-IDF 加了 assert（`esp_task_stack_is_sane_cache_disabled`）在 cache_disable 前检查当前任务栈是否在 SPIRAM，若是则直接 abort，避免随机崩溃。

## 修复
[ui_port.c:96-107](main/ui/ui_port.c#L96-L107)：

```diff
+ // ★ 栈必须在内部 SRAM：LVGL 任务会通过 GIF/字体加载触发 SPIFFS 读 Flash，
+ //   Flash 操作期间 ESP-IDF 临时关闭 cache，SPIRAM 不可访问，栈在 SPIRAM 会触发
+ //   cache_utils.c:152 assert(esp_task_stack_is_sane_cache_disabled) 崩溃。
+ //   现在内部 SRAM 充足（>150KB），8KB 栈完全负担得起。
  const lvgl_port_cfg_t lvgl_cfg = {
      .task_priority = 3,
      .task_stack = 8192,
      ...
-     .task_stack_caps = MALLOC_CAP_SPIRAM
+     .task_stack_caps = MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT,
  };
```

前提：BUG-009 修复后内部 SRAM 已回血到 170KB，8KB 栈完全有余。

## 教训 / 通用规则

**ESP-IDF 硬性限制**：任何会调用以下操作的任务，栈必须在内部 SRAM：
- SPI Flash 读写（`esp_flash_*`、`esp_partition_*`）
- SPIFFS / FAT 文件 IO（底层走 esp_partition）
- NVS 读写（`nvs_set_*`、`nvs_get_*`）
- OTA 升级
- 任何会触发 `spi_flash_disable_interrupts_caches_and_other_cpu` 的 API

**项目内同类已知坑（避免重复）**：
| 任务 | 文件 | 栈位置 | 原因 |
|---|---|---|---|
| `ws_reconn` | [session.c:318-323](main/session/session.c#L318-L323) | INTERNAL | NVS 写 token |
| `async_ww_update` | [mqtt_protocol.c:307-314](main/protocol/mqtt_protocol.c#L307-L314) | INTERNAL | NVS 写唤醒词 |
| `lvgl_port_task` | [ui_port.c:103](main/ui/ui_port.c#L103) | INTERNAL（本 BUG 修复） | GIF 读 SPIFFS |

## How to apply

新增任何任务时，问自己：
1. 这个任务会直接或间接读写 Flash/NVS/SPIFFS 吗？
2. 如果是 LVGL task 而 UI 资源在 Flash → **必须** `MALLOC_CAP_INTERNAL`
3. 如果只是数据处理、网络通信、PWM 控制 → 可以 `MALLOC_CAP_SPIRAM` 省内部 SRAM
4. **不确定时优先 INTERNAL**，等内部 SRAM 紧张了再迁移
