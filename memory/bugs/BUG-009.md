# BUG-009：LVGL 内置 TLSF 静态池吃 64KB 内部 SRAM

## 状态
✅ 已修复（2026-04-26）

## 症状
```
I (12687) UI_PORT: Free SRAM: 11371 bytes
E (12697) LVGL: lvgl_port_init(93): Create LVGL task fail!
Guru Meditation Error: Core 0 panic'ed (LoadProhibited)
→ eye_gif_show2 (ui_port.c:62)
→ lv_obj_set_style_bg_color(NULL, ...) → strlen access 0x28 → 重启循环
```

后续日志显示 `[heap] internal free: 3319 B`，内部 SRAM 几乎榨干。

## 根因
[sdkconfig:2571](sdkconfig#L2571) 配置：
```
CONFIG_LV_USE_BUILTIN_MALLOC=y
CONFIG_LV_MEM_SIZE_KILOBYTES=64
CONFIG_LV_MEM_ADR=0x0   # 0 表示用静态全局数组
```

效果：LVGL 在编译期生成一个 `lv_mem_buf[65536]` 静态数组，链接到 DRAM 段。
**程序加载即占用 64KB 内部 SRAM**，与是否调用 LVGL 无关。

叠加其他系统占用（WiFi 静态 23KB、SPIRAM_MALLOC_RESERVE_INTERNAL 32KB、ESP-IDF/FreeRTOS ~30KB、应用任务、MQTT 等），到 `ui_init()` 时只剩 11KB，无法分配 LVGL task 8KB 栈 + TCB → `xTaskCreate` 失败。

更糟的是 [ui_port.c:160](main/ui/ui_port.c#L160) 的 `ui_init()` 忽略 `app_lvgl_init()` 返回值，继续调 `eye_gif_show2()` → `lv_screen_active()` 返回 NULL → 解引用崩溃 → 重启循环。

## 修复
[sdkconfig:2571-2572](sdkconfig#L2571-L2572) + [sdkconfig.defaults:18-21](sdkconfig.defaults#L18-L21)：

```diff
- CONFIG_LV_USE_BUILTIN_MALLOC=y
- # CONFIG_LV_USE_CLIB_MALLOC is not set
+ # CONFIG_LV_USE_BUILTIN_MALLOC is not set
+ CONFIG_LV_USE_CLIB_MALLOC=y
```

LVGL 改用 stdlib malloc → ESP-IDF heap_caps_malloc 按需分配，不再静态预留 64KB。

## 验证
| 节点 | 改前 | 改后 |
|---|---|---|
| 启动时 internal free | 不详 | **221 KB** |
| ui_init LVGL 前 | **11 KB** | **170 KB** |
| 唤醒词前 | 3 KB | 130 KB |

净增 ~159 KB 内部 SRAM。

## 教训 / How to apply

1. **任何引入 LVGL/UI 的项目**第一时间检查 `LV_USE_BUILTIN_MALLOC` 与 `LV_MEM_SIZE_KILOBYTES` 配置，默认值会静吞 64KB DRAM。
2. ESP32-S3 等 SPIRAM 设备应优先 `LV_USE_CLIB_MALLOC=y`，让 LVGL 走系统 heap，受 `SPIRAM_MALLOC_ALWAYSINTERNAL` 阈值控制。
3. **错误返回值必须检查**：`app_lvgl_init()` 失败必须 return，否则后续 `lv_screen_active()` 返回 NULL 会引发更难排查的 LoadProhibited。
4. 排查内部 SRAM 不足时，**先看静态分配（TLSF 池、WiFi static buffer、CONFIG_SPIRAM_MALLOC_RESERVE_INTERNAL）**，再看动态分配，前者通常一次回血 30KB+。
