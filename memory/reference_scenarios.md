# 四大场景命令

> 使用方式：说"场景1"/"查看结构" 或 "场景2"/"修复bug" 等，自动执行对应的完整流程。

---

## 场景 1：查看代码结构、理解项目

**触发词**: "场景1" / "查看结构" / "梳理代码" / "代码结构"

**执行流程**:
1. 列出 `main/` 目录下所有 .c/.h 文件，说明每个文件的作用
2. 画出代码调用关系图（文字描述）
3. 定位项目入口函数，描述核心流程

---

## 场景 2：修复 Bug、解决编译错误

**触发词**: "场景2" / "修复bug" / 直接贴报错日志

**执行流程**:
1. 分析错误原因，用中文解释
2. 定位出错的文件和代码行
3. 修复问题，修改后自动重新编译验证
4. 记录到踩坑日志（如果是新坑点）

---

## 场景 3：升级功能、添加新代码

**触发词**: "场景3" / "添加功能" / "我想加 xxx"

**执行流程**:
1. 分析需要修改哪些文件
2. 写出完整实现代码，遵循项目纯 C 规范和 snake_case 命名
3. 修改后自动编译检查，确保无错误
4. 说明新增代码的逻辑
5. 记录到决策日志（如果涉及架构决策）

---

## 场景 4：优化代码、提升性能

**触发词**: "场景4" / "优化代码" / "检查优化"

**执行流程**:
1. 检查内存泄漏、冗余代码、可简化逻辑
2. 优化代码可读性，添加详细中文注释
3. 在不改变功能的前提下提升稳定性
4. 优化后自动编译验证，列出所有修改点
5. 更新踩坑日志（如果发现新问题）
