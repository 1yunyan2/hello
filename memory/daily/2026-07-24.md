# 每日总结 2026-07-24

## 会话主题：HTTPS/WSS 迁移 + BluFi 蓝牙名修复

---

## 一、完成事项

### 1. Auth 接口迁移 HTTP → HTTPS
- **问题**：`AUTH_LOGIN_URL` 改为 `https://api.strailine-space.com/...` 后，TLS 握手报 `ESP_ERR_MBEDTLS_SSL_SETUP_FAILED`
- **修复**：[auth.c:14](../main/protocol/auth.c) 加 `#include "esp_crt_bundle.h"`；[:157](../main/protocol/auth.c) 加 `.crt_bundle_attach = esp_crt_bundle_attach`
- **结果**：`esp-x509-crt-bundle: Certificate validated` 验证通过，accessToken 获取成功

### 2. WebSocket WSS 连接修复
- **问题**：WS 地址改为 `wss://ai.strailine-space.com/ws/omni` 后，websocket_client.c:521 的 `crt_bundle_attach` 一直被注释
- **修复**：取消注释 `.crt_bundle_attach = esp_crt_bundle_attach`
- **结果**：WSS TLS 握手可正常建立

### 3. main 任务栈溢出修复
- **问题**：`CONFIG_ESP_MAIN_TASK_STACK_SIZE=3584`，多模块同时初始化（Auth+MQTT+触摸）栈帧叠加溢出
- **修复**：sdkconfig 改为 `8192`
- **根因**：不是单纯因为 HTTPS，main 本来就处于临界状态，HTTPS 是压垮的最后一根稻草

### 4. BluFi 蓝牙广播名修复
- **问题**：手机扫到的是 `BLUFI_DEVICE`（ESP-IDF 框架默认值），而非预期的 `EchoPals-D485C4`
- **根因**：`esp_blufi_host_and_cb_init()` 启动 NimBLE 是异步的，`ble_svc_gap_device_name_set()` 在之后调用时广播已经开始，名字没生效
- **修复**：
  - blufi_init.c 新增 `blufi_set_device_name()` + 全局 `s_ble_device_name[]`
  - `blufi_on_sync` 回调里先设名字再 `profile_init`
  - blufi_security.h 加函数声明
  - bsp_wifi.c 改为 `blufi_set_device_name(service_name)` 并移到 `host_and_cb_init` 之前

---

## 二、知识点

- HTTPS = HTTP + TLS，ESP32 无系统级证书库，必须手动 `crt_bundle_attach`
- NimBLE 主机启动是异步的，设备名必须在 `sync` 回调触发前写入静态变量，由 `blufi_on_sync` 统一设置
- `main` 任务栈 3584 是历史遗留默认值，跑 HTTPS/MQTT 多模块应改为 8192+
