## 一、总述

本次会话只改一个文件 [main/games/game_race.c](main/games/game_race.c)，做的是**减法**：
把原来「难度选择 → 倒计时 → 游戏(显示分数+高分) → 结算(得分+历史最高+突破记录)」
四态流程，砍成「倒计时 → 游戏(不显示分数) → 结算(游戏结束+得分)」三态流程。

需求经过一轮修正：**第一版方向做反了**——我按字面理解把结算界面整个删掉（撞车直接重开），
用户随即指出「撞到本来就没有画面，不然没法知道得了多少分」，真实意图是
**游戏过程中不显示分数、把分数挪到结算界面显示**。第二版按修正后的理解重做。

所有移除均为**真删除而非注释**（C 工程通常开 `-Werror`，留下未使用的函数/变量会触发
`-Wunused-function` / `-Wunused-variable`）。用户中途专门追问过这一点。

## 四、经验沉淀

- **「去除 X 界面」要先确认去的是界面本身还是界面里的某些元素**。本次第一版把结算整个删掉，
  导致玩家撞车后瞬间重开、根本看不到得分。用户的原话「不然没法知道」点破了真实约束：
  **分数必须有一个可见的落点**，把它从游戏中挪走的前提是结算界面要接住它。
- **删代码要连带清理唯一调用方已消失的函数**。`game_timers_stop()` 只被 `enter_select()` 调用，
  删了后者不删前者，`-Werror=unused-function` 直接编译失败。同类：`hud_refresh()`。
- **删了赋值但保留局部变量时用 `(void)var;` 兜底**（如 `engine_cb` 的 `dirty`），
  比删掉整条赋值链路改动更小、更不容易引入逻辑错误。
- **裁剪中文字库的项目改 UI 文案是高危操作**。`font_cn_16` / `font_cn_32` 都是按用字裁剪的，
  换文案 = 可能缺字。历史上 [2026-06-24 天气页](2026-06-24_weather_ui.md) 已踩过一次
  （`font_cn_32` 没有 `°` 只能显示数字）。改文案后务必实机看一眼有无方块。
- **宏和结构体字段未使用不报警告，函数和变量会**。所以 `RACE_NVS_NS`、`nvs_key` 可以安全留着，
  但 `highscore_load()`、`g.high_score` 必须删干净。
