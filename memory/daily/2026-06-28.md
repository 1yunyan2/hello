# 每日总结 2026-06-28

## 主题：USB插着时禁止进入任何级别低功耗待机

---

## 问题描述

设备插着USB供电时，仍然会按时触发一/二/三级待机，日志现象：

```
I (66797) STANDBY: 无活动超过 40000 ms，进入待机
W (86857) STANDBY: 无活动超过 60000 ms，进入二级待机（关屏 + 停舵机，CPU 不睡，闹钟照常）
W (83077) STANDBY: 无活动超过 70000 ms，执行纯关机（断电）
I BOD: Brownout detector was triggered
```

三级关机执行 `esp_restart()` 后，USB 又将芯片重新拉起，表现为"断电后自动重连"。

---

## 根因分析

### 1. 硬件层：无独立VBUS检测脚

板子引脚全部用满（编解码器、触摸×5、LCD×6、马达、舵机×3、电池ADC、关机控制、BOOT），没有任何空闲引脚可以接USB 5V检测电路。

### 2. 软件层：`bsp_battery_is_charging()` 在满电时永远返回 false

[main/bsp/bsp_battery.c:478] 的充电判定逻辑：只有 OCV **持续明显上升**（每次 ≥30mV，连续3次）才判定为"充电中"。

**问题**：电池满电时（OCV ≥ 4000mV），插着USB电压基本持平，不再持续上升，凑不够3次连续上升，`s_ctx.charging` 永远是 `false`。

[main/ui/standby.c:201] 的三级关机里原有充电豁免逻辑因此完全失效。

---

## 修复方案

### 修改1：`bsp_battery.c` — 满电区直接判定为充电中

**文件**：[main/bsp/bsp_battery.c](../main/bsp/bsp_battery.c)  
**位置**：原充电判定块（原478行）

新逻辑：
- OCV ≥ `BSP_BAT_HIGH_VOLT_UNLOCK_MV`（4000mV，已有宏）时，**直接判定为充电中**，不要求持续上升趋势
- 满电区内若 OCV 出现明显下降（≥30mV），才退出充电态（说明真的在放电/拔了USB）
- OCV < 4000mV 时维持原有连续上升趋势判断（非满电场景充电仍能正常识别）

### 修改2：`standby.c` — 充电中刷新活动时间戳，跳过所有级别待机

**文件**：[main/ui/standby.c](../main/ui/standby.c)  
**位置**：`standby_task` while(1) 循环开头，step 1b（新增）

```c
// ── 1b. 正在充电（USB/适配器供电）即视为活动 ─────────────────────
if (bsp_battery_is_charging())
    touch_activity();
```

每秒调用一次 `bsp_battery_is_charging()`，该函数只是读 `s_ctx.charging` 内存变量，不触发ADC采样，**无额外功耗**。`standby_task` 本身本来就是1秒周期，不是新增轮询。

---

## 覆盖场景

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 插USB、电池满电 | charging=false → 照常进入三级关机 | OCV≥4000mV直接charging=true → standby永远刷新时间戳 → 不进任何级别 |
| 插USB、电池未满（充电中） | OCV持续上升→charging=true → 三级豁免，但一/二级仍进入 | charging=true → 一/二/三级全部跳过 |
| 不插USB、正常放电 | 正常进入各级待机 | OCV持续下降不满足上升条件 → charging=false → 行为不变 |

## 注意事项

- 三级关机内原有的 `bsp_battery_is_charging()` 充电豁免分支（standby.c:201）现在变为冗余兜底，保留不删
- `BSP_BAT_HIGH_VOLT_UNLOCK_MV = 4000mV` 是本项目已有定义（bsp_config.h:314），不是新引入的魔数
