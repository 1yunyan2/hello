# 每日总结 2026-06-30 — 三级断电排查

## 概述

本次会话围绕 standby.c 三级低功耗（硬件断电）的可行性验证与根因排查展开。

---

## 主要发现

### 1. 三级断电机制验证

- **硬件链路**：GPIO18(OPT-OUT) → R29(1kΩ) → HK015T.1 IO1 → 内部逻辑 → Q4(SS8050 NPN) → Q3(AO3401A PMOS) → 切断 VCC_IN 主电源
- **IO1 实测电压**：正常工作时为 **1.45V**（分压中间态，非强推挽输出），说明 HK015T.1 没有强驱动这条线，GPIO18 可以影响该节点
- **低电关机链路从未实测验证过**（之前注释写"已验证"是误判，实际上电池从未真正放到触发低电关机）

### 2. 插 USB 测试无效

- USB 供电独立于 HK015T.1 自锁开关，即使关机指令生效、切断电池主路，ESP32 仍被 USB 供电，表现为重启而非断电
- 插着 USB 也不能进入低功耗（`standby_task` 里检测到充电就刷新计时）
- **结论：所有三级断电测试必须纯电池供电**

### 3. 满电误判为"正在充电"问题

- `bsp_battery.c` 里满电区（OCV≥4000mV）直接判定 `s_ctx.charging = true`，原本是为解决UI百分比显示问题
- `standby_task` 里新增了 `if (bsp_battery_is_charging()) touch_activity()` 导致满电时一级待机永远进不去
- **表现**：一级进入时间从 40s 变成一分多钟（等电压自然消耗降到 4000mV 以下才触发）

### 4. 三级"两次才断电"根因排查过程

| 尝试 | 做了什么 | 结果 |
|------|---------|------|
| 原始版本 | 拉高 GPIO18 + 自旋等待 | 系统继续跑，从不断电 |
| 加 `esp_restart()` | 拉高 GPIO18 → 100ms → `esp_restart()` | 第一次：复位重启；第二次：真断电 |
| 加边沿 + 拉长保持 | 先拉低500ms → 再拉高500ms → `esp_restart()` | 依然是第一次复位重启、第二次断电 |
| 去掉 `esp_restart`，纯保持 | 拉低5s → 拉高 → 自旋保持 | 待测 |

**当前最可信猜测**：HK015T.1 可能需要 IO1 上累积足够时长/能量（类似"长按"逻辑），第一次加上复位过程的时间才刚好接近门限，第二次在此基础上累加才越过门限。验证方法：大幅拉长单次保持时间（5秒）看第一次能否成功。

### 5. 当前代码最终状态（2026-06-30 末）

`standby.c` 已经有大量额外改动（非本次会话引入）：
- 删除了一级轻度待机，改为"直接二级深度待机"双级模型
- 增加了进待机后"等 settle 再取基准电压"的插 USB 检测逻辑
- 增加了关机前震动提醒（`STANDBY_SHUTDOWN_WARN_MS`）
- 三级关机已改为调用 `bsp_battery_power_off()`（封装在 bsp_battery.c）
- 有断电前电压复查逻辑（`STANDBY_PWR_RECHECK_RISE_MV`）
