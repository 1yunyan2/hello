# 修复 WebSocket 重连内存泄漏

## 问题根因

`session_reconnect_task` 中 `session.c:959-968` 的 "Token 未变" 重连路径：

```c
protocol_disconnect(s_protocol);   // esp_websocket_client_stop
protocol_connect(s_protocol);      // esp_websocket_client_start
```

`esp_websocket_client_stop()` + `esp_websocket_client_start()` 在 401 失败路径上：
- 内部 task 已因错误退出，`stop()` 无法正确等待其清理
- `start()` 创建新 task（新栈分配 ~4KB）+ 重新初始化传输层缓冲区
- 旧 task 栈 + 旧传输层缓冲区的内存未被释放 → 每次泄漏 ~6.5KB

## 修复方案

将 `stop+start` 改为 `destroy+create`（完整生命周期管理），并在两者之间加 `vTaskDelay` 给 FreeRTOS idle task 时间清理已删除 task 的栈内存。

### 修改文件：`main/session/session.c`

**替换 `session_reconnect_task` 中第 959-968 行的 "Token 未变" 路径：**

原代码：
```c
// ★ 普通重连（Token 未变）：直接 stop+start 复用现有客户端对象
// 避免每次重连都 destroy+create 导致 esp_websocket_client 内部缓冲区反复分配，
// 引发内部 SRAM 每次丢 ~5KB 的碎片化泄漏
if (s_protocol != NULL && !token_refreshed)
{
    ESP_LOGI(TAG, "Token 未变，复用 WebSocket 客户端对象直接重连...");
    protocol_disconnect(s_protocol);
    protocol_connect(s_protocol);
    ESP_LOGI(TAG, "重连完成，WebSocket 正在建立连接... URI: %s", s_ws_uri);
    goto exit_task;
}
```

替换为：
```c
// ★ 普通重连（Token 未变）：销毁旧连接再重建，彻底释放内部 task 栈和传输缓冲区
// stop+start 无法释放 esp_websocket_client 内部已退出 task 的栈（~4KB）+
// 传输层缓冲区，导致每次重连泄漏 ~6.5KB 内部 SRAM
if (s_protocol != NULL && !token_refreshed)
{
    ESP_LOGI(TAG, "Token 未变，销毁旧连接并重建以释放内存...");
    protocol_disconnect(s_protocol);
    protocol_destroy(s_protocol);
    s_protocol = NULL;

    // 等待 FreeRTOS idle task 清理已删除的内部 task 栈内存
    vTaskDelay(pdMS_TO_TICKS(100));

    char *full_ws_uri = (char *)malloc_zeroed(1024);
    if (full_ws_uri == NULL)
    {
        ESP_LOGE(TAG, "full_ws_uri 分配失败，放弃重连");
        goto exit_task;
    }

    if (strlen(s_access_token) > 0)
        snprintf(full_ws_uri, 1024, "%s?token=%s", s_ws_uri, s_access_token);
    else
        strncpy(full_ws_uri, s_ws_uri, 1024 - 1);

    s_protocol = protocol_create(full_ws_uri, s_access_token);
    free(full_ws_uri);

    if (s_protocol == NULL)
    {
        ESP_LOGE(TAG, "protocol_create 失败，内存不足，放弃重连");
        goto exit_task;
    }

    protocol_register_callback(s_protocol, protocol_event_handler, NULL);
    protocol_connect(s_protocol);
    ESP_LOGI(TAG, "重连完成，WebSocket 正在建立连接... URI: %s", s_ws_uri);
    goto exit_task;
}
```

### 为什么这次 destroy+create 不会再泄漏

原注释说 "destroy+create 导致每次丢 ~5KB 碎片化泄漏"，原因是当时没有加 `vTaskDelay(100)` 让 idle task 清理已删除 task 的栈。`esp_websocket_client_destroy` 内部调用 `stop` 后立即释放结构体，但底层 task 的 FreeRTOS TCB + 栈需要 idle task 异步回收。不等这 100ms 就重新 `init`，会导致新旧内存重叠分配，产生碎片。加了 delay 后 idle task 能及时回收，destroy 分配的所有内存都能被 `free` 正确释放。

## 验证方法

烧录后观察日志中 `握手前` 的内部 RAM 数值，连续多次 401 重连后该值应保持稳定，不再持续下降。
