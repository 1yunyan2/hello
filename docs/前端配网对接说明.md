# Echo2 设备 BluFi 配网 —— 前端对接说明

> 面向：小程序 / App 前端开发
> 设备端已完成并自测通过，本文档为对接规范。

## 一、总览

设备配网基于 **乐鑫 BluFi 标准协议**（蓝牙 BLE 通道传 WiFi 凭证），不是私有协议。
前端只需按 BluFi 标准对接即可，**强烈建议直接使用现成的 BluFi 协议库**，不要自己拼蓝牙数据帧。

配网要完成两件事：
1. **传 WiFi 账号密码** → 让设备联网
2. **下发 deviceToken** → 让设备能连业务服务器（认证用）

## 二、设备 BLE 标识（固定）

| 项 | 值 | 说明 |
|---|---|---|
| 广播名 | `EchoPals-XXXXXX` | XXXXXX 为设备 MAC 后三字节，如 `EchoPals-8C6BF8` |
| 服务 UUID | `0xFFFF` | BluFi 标准服务，库会自动识别 |
| 写特征(手机→设备) | `0xFF01` | 库自动处理 |
| 通知特征(设备→手机) | `0xFF02` | 库自动处理 |

UUID 都是 BluFi 协议固定值，用 BluFi 库时无需手动填写。

## 三、配网流程（BluFi 标准）

1. 打开蓝牙 + 定位权限（安卓扫 BLE 必须有定位权限且定位总开关打开）
2. 扫描，找到名称以 `EchoPals-` 开头的设备
3. 连接设备（建立 GATT，自动发现 0xFFFF 服务）
4. （可选）安全协商 / 协商加密
5. **请求设备扫描 WiFi 列表** → 设备返回周边 WiFi 供用户选择（设备端已实现，见下）
6. 发送选定的 WiFi SSID
7. 发送 WiFi 密码
8. **发送自定义数据下发 token**（见第四节）
9. 发送"连接 AP"指令
10. 查询设备 WiFi 状态，确认 `got IP` = 配网成功

> 注：设备配网成功后会主动断开蓝牙（释放内存），前端看到"断开"属正常，是配网成功的标志，不是失败。

## 四、下发 deviceToken（关键，业务自定义部分）

配网过程中，必须通过 BluFi 的 **自定义数据(Custom Data)** 通道下发设备凭证：

- 调用 BluFi 库的发送自定义数据接口（如 `postCustomData`）
- 内容为 **JSON 字符串**：`{"token":"<deviceToken>"}`
- 编码 UTF-8，长度 < 2048 字节
- `<deviceToken>` 由后端在设备绑定时生成（前端从后端接口获取）

⚠️ 格式约定（设备端按此解析，必须一致）：
- 必须是合法 JSON，且含 `token` 字段
- 不能直接发裸字符串（如直接发 `abc123`），否则设备解析失败

设备收到后会存入 NVS，并自动用它去业务后端换取 accessToken 连接服务器。

## 五、设备端已实现的能力（自测通过）

设备端已用标准 BluFi 客户端完成全链路实测，以下能力可用：

- ✅ BLE 广播 + 连接 + 0xFFFF 服务发现
- ✅ 接收 WiFi SSID / 密码并联网（实测 `got IP`、MQTT 上线成功）
- ✅ **扫描并返回周边 WiFi 列表**（前端"获取 WiFi 列表"功能依赖此项，已实现）
- ✅ 接收自定义数据 `{"token":"..."}` 并存储（实测设备成功提取 token 并触发换取 accessToken）

## 六、前端需要后端配合确认的事项

deviceToken 的发放规则在后端，前端对接前请向后端确认：
1. 如何为设备获取 deviceToken（设备绑定流程）
2. deviceToken 的有效期与刷新方式
