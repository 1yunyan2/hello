# 断网离线模式 开发文档

> 版本：v1.0　　日期：2026-08-03　　分支：`thre`
> 目标：WiFi 运行态重连 5 次失败后**不再软复位重启**，改为进入**永久离线模式**：
> 彻底停止一切重连尝试、关闭射频、关停所有依赖 WiFi 的功能，只保留不依赖网络的
> 本地外设与功能（GIF/舵机/震动/触摸/游戏/唤醒词/本地音频/按键/低功耗）。
> **恢复联网方式：用户手动关机再开机**（本模式内不提供任何软件恢复入口）。

---

## 一、现状（改造前的真实行为）

日志证据与代码对应关系：

| 日志 | 代码位置 | 行为 |
|---|---|---|
| `WiFi 掉线，正在重连... (5/5)` | `bsp_wifi.c:782-784` | 额度内 `esp_wifi_connect()` |
| `重连已达上限 (5)，启动 8000 ms 复位看门狗（期间仍尝试自愈）` | `bsp_wifi.c:800-807` | ⭐**满 5 次后仍然继续 `esp_wifi_connect()`**，只是额外挂一个 8s 看门狗 |
| `WiFi 重连 5 次全部失败，且缓冲 8000 ms 内仍未恢复 → 软复位刷新设备` | `bsp_wifi.c:138-144` | 看门狗到期 `esp_restart()` |
| `Auth 第 1/3 次尝试...` / `Auth 失败，5 秒后重试...` | `session.c:1107-1142` | `ws_reconn` 任务**无限重试循环**，与 WiFi 状态无关 |
| `MQTT 第 3 次重连，20 秒后执行...` | `mqtt_protocol.c:256-309` | `mqtt_reconn` 任务**无限退避循环**，与 WiFi 状态无关 |
| `IP 定位失败，保留默认城市` / `天气获取失败` | `reminder.c:856-861` | 天气拉取无网络判断，**同步阻塞**提醒任务 |

**结论：离线模式代码从未存在。** 全仓库 `grep -i offline` 仅命中 `offline_audio.c/h`
（本地 MP3/P3 播放模块），与网络无关。当前行为是 `bsp_wifi.c:788-799` 注释中明确
记录的**有意设计**（早期"满 5 次置 `WIFI_FAIL_BIT` 永久放弃"导致运行态无人接管、
设备彻底卡死，才改成"继续重连 + 看门狗兜底重启"）。

> ⚠️ 改造必须避免重蹈那个坑：新方案不是"什么都不做地卡死"，而是**主动关停 + 明确置位 +
> 让所有网络消费者提前返回**，任何任务都不得停在无出口的等待里。

## 二、设计原则

1. **单一事实来源**：新增一个全局"运行态离线标志" `s_offline_mode`，由 `bsp_wifi.c`
   唯一置位，其余模块只读。区别于瞬时的 `WIFI_BIT`（抖动即变），本标志**一旦置位，
   本次开机周期内永不清除**。
2. **不重启、不恢复**：满 5 次即进入离线，不启动复位看门狗，不再 `esp_wifi_connect()`。
   恢复只能靠用户手动关机重开（冷启动后所有静态变量自然复位）。
3. **主动关停而非被动跳过**：不能只让网络任务"空转但跳过请求"——那样任务、socket、
   mbedTLS 上下文仍在，白耗 SRAM/PSRAM。必须让重连任务**真正退出并自删**。
4. **退出必须用 `vTaskDeleteWithCaps`**：`ws_reconn`(6KB INTERNAL) 与 `mqtt_reconn`
   (3KB SPIRAM) 均由 `xTaskCreatePinnedToCoreWithCaps` 创建，普通 `vTaskDelete` 会
   泄漏栈+TCB（BUG-023 原文）。
5. **不碰不相关代码**：只在必要位置加"离线拦截"分支，不重构现有重连逻辑。

## 三、新增基础设施

### 3.1 接口（`bsp_board.h`）

```c
/**
 * @brief 查询设备是否已进入"运行态离线模式"。
 *
 * 运行态 WiFi 重连达 MAX_RETRY_COUNT 次仍失败后由 bsp_wifi 置位，
 * 本次开机周期内永不清除；恢复联网需用户手动关机重开。
 *
 * @return true = 已离线（所有网络功能必须跳过）
 */
bool bsp_wifi_is_offline_mode(void);
```

### 3.2 实现（`bsp_wifi.c`）

```c
/// @brief 运行态离线模式标志：置位后永不清除（恢复需手动关机重开）。
/// volatile：由 sys_evt 事件回调置位，被多个任务读取。
static volatile bool s_offline_mode = false;

bool bsp_wifi_is_offline_mode(void) { return s_offline_mode; }
```

## 四、改动清单（逐文件）

### 4.1 `bsp_wifi.c` —— 核心：满 5 次进入离线

**位置**：`bsp_wifi.c:786-816`（`else` 分支，重连额度耗尽处）

**改前**：`esp_wifi_connect()` + 启动 `s_wifi_reset_timer`（8s 后 `esp_restart()`）。

**改后**：

```
置 s_offline_mode = true
停掉复位看门狗 s_wifi_reset_timer（防止残留计时触发重启）
停掉去抖定时器 s_wifi_debounce_timer，并立即清 WIFI_BIT（不再等 1.5s 去抖）
udp_logger_stop()
esp_wifi_disconnect()  → 停止驱动层自动重连
esp_wifi_stop()        → 关射频，省电（不 deinit，避免释放期与事件回调竞态）
打印醒目日志：已进入离线模式，需手动关机重开
```

**注意事项**：
- `esp_wifi_stop()` 会再产生一次 `WIFI_EVENT_STA_DISCONNECTED`。必须在**事件处理函数
  最开头**加离线短路：`if (s_offline_mode) return;`，否则会递归回到本分支。
- 复位看门狗回调 `wifi_reset_watchdog_cb`（`:138`）内也加一道保险：
  `if (s_offline_mode) return;`，杜绝"定时器已在运行、stop 有竞态窗口"时误重启。
- 本分支运行在 `sys_evt` 任务上（栈仅 2304B），**只做置位 + 停定时器 + wifi stop，
  禁止打日志以外的重活**（NVS 写、UI 调用等一律不做）——这是解绑必崩的同款坑。

### 4.2 `session.c` —— WebSocket 重连任务退出 + 唤醒词拦截

**(a) 重连任务循环入口**：`session.c:1107` `while (true)` 循环体最开头

```
if (bsp_wifi_is_offline_mode()) {
    打印"离线模式，停止 WebSocket 重连"
    加锁销毁 s_protocol（disconnect_timeout + destroy + NULL）
    清理 s_reconnecting / s_reconnect_handle / s_reconnect_attempts
    vTaskDeleteWithCaps(NULL);   // 必须 WithCaps：6KB 内部 SRAM 栈
}
```

同时在 `:1097` 的首次退避 `vTaskDelay` **之后**也要再判一次（退避期间可能刚好进离线）。

**(b) 重连任务创建点**：`session.c:290` —— 离线时直接不创建。

**(c) 唤醒词入口**：`session_on_wake_word()`（`:1488`）在 `s_ota_locked` 判断之后追加

```
if (bsp_wifi_is_offline_mode()) {
    打印"离线模式，唤醒词不发起云端会话"
    return WAKE_IGNORED;
}
```

> 说明：唤醒词本身是**本地** MultiNet 识别，离线可用；这里拦的是它**触发云端会话**
> 的部分。唤醒引擎不停（游戏内唤醒词是故意保留的功能，见 BUG-035 记录）。

### 4.3 `mqtt_protocol.c` —— MQTT 重连任务退出 + 启动拦截

**(a) 重连任务循环**：`mqtt_protocol.c:256` `while(1)` 最开头

```
if (bsp_wifi_is_offline_mode()) {
    打印"离线模式，停止 MQTT 重连"
    break;   // 走已有的 s_mqtt_reconnect_handle=NULL + vTaskDeleteWithCaps 收尾
}
```
放在 `vTaskDelay` 退避**之后**判断（退避期间进离线也能立刻退出）。

**(b) 任务创建点**：`mqtt_protocol.c:716` —— 离线时不创建重连任务。

**(c) `protocol_mqtt_start()`**（`:744`）—— 离线时直接 return，不发起连接。

### 4.4 `reminder.c` —— 天气拉取拦截（优先级最高：唯一阻塞点）

**位置**：`reminder.c:856-861` `case REM_EVT_WEATHER_FETCH`

```
if (bsp_wifi_is_offline_mode()) {
    打印"离线模式，跳过天气播报"
    break;   // 不调 weather_fetch_and_notify()
}
```

> 为什么优先级最高：`weather_fetch_and_notify()` 是**同步 HTTP**，离线时每次要走完
> DNS 失败 → connect 失败的完整超时链路（日志里 `ip-api.com` getaddrinfo 202 那段），
> 整个 reminder 任务被阻塞住，闹钟/日历触发会被拖延。

**本地时间与闹钟不受影响**：闹钟/日历存 NVS、纯本地判断，只依赖系统时间。
`s_ctx.sntp_synced` 若从未同步过会导致时间不准，但**不阻断触发**（本轮不做 NVS 时间
兜底，见"第六节 本轮不做"）。

### 4.5 `bsp_ota.c` —— OTA 拦截

**位置**：`bsp_ota_trigger()`（`:456`）参数校验之后、malloc 之前

```
if (bsp_wifi_is_offline_mode()) {
    打印"离线模式，拒绝 OTA"
    return ESP_ERR_INVALID_STATE;
}
```

## 六、本轮**不做**的（明确划界）

用户已确认："恢复联网需要用户手动开关机，不用管联网。"因此以下 07-21 旧设计中的
条目本轮**不实现**：

- ❌ SNTP 时间 NVS 兜底（`last_sync_epoch`）
- ❌ 天气结果 NVS 缓存与"陈旧数据"播报
- ❌ 任何软件层的手动恢复联网入口（按键/菜单）
- ❌ 低频后台静默重试

## 八、风险与注意点

1. **`esp_wifi_stop()` 的再入事件**：必输在事件 handler 最开头短路，否则递归。（4.1）
2. **`sys_evt` 栈 2304B**：离线分支只做轻量操作。（4.1）
3. **任务自删必须 `WithCaps`**：否则每次泄漏 6KB 内部 SRAM / 3KB PSRAM（BUG-023）。
4. **定时器残留**：`s_wifi_reset_timer` 与 `s_wifi_debounce_timer` 都要显式 stop，
   并在各自回调内加离线短路做双保险。
5. **不影响配网态**：`s_is_provisioning` 为真时走的是 `s_prov_retry_num` 那套独立逻辑，
   与本改造完全隔离，不得误伤。
6. **不影响开机首连**：开机首连失败走的是 `WIFI_FAIL_BIT` + `bsp_board_wifi_main`
   等待逻辑；本改造只作用于**运行态**（已 GOT_IP 过之后的掉线）。
